## Response contract

Questions: verdict first (yes/no), then one reason. Details only when asked.
Actions: first line before work starts `Actions:` and lists the work in one line.
Status: first line of completion message is `Done` / `Blocked: reason` / `Partial: what`. Then only the requested result; no implementation recap.
Coordinator relay: status line + issue link only.
End every reply with 1–2 lines: what was skipped or not checked, and any risk. This is the ponytail footer — never omit, even for yes/no.

## Navigation

For code lookups, call `jcodemunch_guide` and use symbol tools; keep markdown and docs on plain read/grep.
Use the repo-root AGENTS.md when present; it holds only entry points, main dirs and test locations. If absent, say so and continue. Run the project-map skill only when skill access is allowed. Never put behavioral rules there — global rules here win.
